# Рецепты добычи буром

Тип `ores_and_drills:drill_mining` использует штатный RecipeManager Minecraft
1.21.1, JSON-кодек и сетевой кодек NeoForge. Файлы размещаются в
`data/<namespace>/recipe/<path>.json` (именно `recipe`, в единственном числе).
Изменения применяются командой `/reload`, без пересоздания мира. Рецепты
синхронизируются с клиентом; при установленном JEI доступны в категории «Добыча
буром», с входной рудой, жидкостью, выходом при его явном задании и подходящими бурами.

## Формат

```json
{
  "type": "ores_and_drills:drill_mining",
  "input": "#c:ores/gold",
  "fluid": {"id": "minecraft:water", "amount": 100},
  "minimum_drill_tier": 3,
  "priority": 10,
  "conditions": [
    {"type": "ores_and_drills:dimension", "dimension": "minecraft:overworld"},
    {"type": "ores_and_drills:height", "min": -64, "max": 128}
  ]
}
```

- `input`: тег блоков (`"#c:ores/gold"`) либо список блоков
  (`["minecraft:gold_ore", "minecraft:deepslate_gold_ore"]`). Даже один конкретный
  блок указывается списком. Блоки не обязаны принадлежать тегу руд.
- `fluid`: необязательная жидкость или тег с положительным `amount` в mB. 1000 mB =
  одно ведро. Конкретная жидкость: `{"id":"minecraft:water","amount":100}`;
  тег: `{"tag":"c:sulfuric_acid","amount":100}` (имя тега без `#`).
  Поддерживаются стандартные ингредиенты жидкостей NeoForge, например
  `{"fluid":"minecraft:water","amount":100}`, а также компоненты точного FluidStack
  в существующем формате с `id`. Одновременно `id` и `tag` указывать нельзя.
  Отсутствие поля означает добычу без жидкости. Количество не должно
  превышать вместимость бака выбранного бура, иначе этот бур будет ждать жидкость.
- `minimum_drill_tier`: положительное число, по умолчанию 1. У штатных буров:
  твердотопливный — 1, электрический — 2, продвинутый — 3, улучшенный/ultimate — 4.
  Проверка обычного уровня инструмента также сохраняется. Баки доступны только
  продвинутому и ultimate: два бака по 10 000 и 20 000 mB соответственно.
  Поэтому у рецепта с `fluid` минимальный уровень автоматически поднимается
  до 3: значения 1 и 2 трактуются как 3, а значение 4 сохраняется.
  Бур также добывает руду, только если её может добыть его эквивалентная
  кирка (твердотопливный — каменная, электрический — железная, продвинутый —
  алмазная, ultimate — незеритовая). JEI и EMI показывают итоговый минимум
  не текстом, а слотами буров в левом нижнем углу страницы рецепта: там
  перечислены только буры, способные добыть руду (они же отвечают на «U»).
  Например, у алмазной руды с сухим рецептом уровня 1 там перечислены
  электрический, продвинутый и ultimate буры. Текст «Минимальный уровень
  бура» остаётся только у рецептов выше уровня всех штатных буров.
- `conditions`: необязательный список дополнительных условий, все должны
  выполняться. `dimension` проверяет ID измерения; `height` — включительный диапазон
  Y руды; `biome` — тег биомов (`{"type":"ores_and_drills:biome","tag":"c:is_overworld"}`);
  `redstone` — сигнал у основного блока бура
  (`{"type":"ores_and_drills:redstone","powered":true}`).
- `priority`: целое число, по умолчанию 0. Выше число — выше приоритет.
- `result`: необязательный ItemStack, например
  `{"id":"minecraft:raw_gold","count":2}`. Если поле отсутствует, используется
  существующий дроп исходной руды. Один результат соответствует одной извлечённой
  единице запаса; бонус производительности буров работает как раньше.
- Стандартные `neoforge:conditions` можно использовать для условной загрузки
  рецептов при наличии конкретного мода. Это отдельная механика от `conditions`,
  проверяемых во время добычи.

Поле `fluid.id` принимает **ID жидкости**, а поле `fluid.tag` — имя тега.
Например, для серной кислоты можно использовать конкретный ID
`modern_industrialization:sulfuric_acid` либо общий тег `c:sulfuric_acid`:

```json
{
  "type": "ores_and_drills:drill_mining",
  "input": "#c:ores/uranium",
  "fluid": {"tag": "c:sulfuric_acid", "amount": 100},
  "priority": 10
}
```

Бур проверяет содержимое обоих баков и выбирает первый, где подходящей жидкости
достаточно для полного цикла. Разные жидкости одного тега не смешиваются:
нельзя оплатить расход 100 mB с помощью 50 mB одной и 50 mB другой жидкости.
Пустой тег не разрешает бесплатную добычу: бур ожидает подходящую жидкость,
а ручная добыча остаётся заблокированной. JEI показывает все жидкости тега.
Состав тегов перечитывается при `/reload` вместе с рецептами. Свои теги можно
добавить через `data/<namespace>/tags/fluid/<name>.json` с массивом `values`.

`c:sulfuric_acid` в поле `id` по-прежнему ошибочен. Ошибка
`Parsing error loading recipe ... Unknown registry key ... minecraft:fluid`
означает, что рецепт вообще не загружен: его ограничение ручной добычи также
не действует. Исправьте ID и выполните `/reload`; отсутствие дропа проверяется
по реально загруженным рецептам, а не по наличию файла на диске.

## Выбор рецепта и цикл

Сначала сравниваются `priority`, затем наличие жидкости (специальный рецепт
раньше сухого), затем конкретные списки блоков раньше тегов. Окончательная ничья
разрешается по ID рецепта в алфавитном порядке. Выбирается один рецепт для исходного
блока. Если его условия не выполняются, запас и жидкость не расходуются; перехода
на менее приоритетный сухой рецепт нет. Рецепты разных жидкостей с одинаковым
входом не являются автоматически взаимозаменяемыми: приоритет должен определять
нужный вариант.

Для `ore_deposit` проверяется настоящая руда из attachment, а не технический блок
контейнера. Сканер находит подходящие рецепты в прежней области добычи. Если в
области есть другие доступные руды, бур может добывать их, пока специальная руда
ожидает жидкость. Если доступных целей нет, прогресс приостанавливается, энергия
на добычу не расходуется. Уже зажжённое топливо твердотопливного бура продолжает
гореть по прежним правилам печи.

Расход жидкости происходит один раз на каждый успешно использованный рецепт за
цикл. Сейчас штатные буры извлекают одну единицу за цикл. Если будущий бур
извлечёт несколько единиц по одному рецепту, жидкость спишется один раз, а запас
уменьшится на число извлечённых единиц. Если в одном цикле используются разные
рецепты, каждый оплачивается отдельно. Заблокированный выход, неподходящая
жидкость и неудачная добыча не расходуют жидкость. Завершение залежи сохраняет
переход в `exhausted_ore_deposit` и прежний учёт оставшегося ресурса.

## Ручная добыча и жидкостные порты

Если хотя бы один загруженный рецепт исходной руды требует жидкость, ручная
добыча любым инструментом не даёт предметов и опыта, независимо от текущих
условий рецепта и зачарований. Обычный блок разрушается. У `ore_deposit` каждое
успешное ручное ломание расходует одну единицу запаса без дропа и опыта.
Физический блок сохраняется, пока запас положителен; после последней единицы
он превращается в `exhausted_ore_deposit`, как при обычном истощении.
Это правило также действует при прямом вызове добычи инструментами по области.
Jade для такой руды показывает красное «✕ Нельзя добыть вручную» и пояснение
«Нужен бур с жидкостью» вместо обычного индикатора кирки. Это работает как для
`ore_deposit`, так и для обычных блоков; запас залежи остаётся виден.
Обычные сухие залежи сохраняют прежнюю ручную добычу по одной единице.

Оба существующих боковых порта продвинутого и ultimate бура доступны трубам на
внешних боковых гранях. Каждый поддерживает заполнение и извлечение через
`IFluidHandler`, включая SIMULATE без изменения содержимого. Порты подключены к
общим двум бакам, а не к отдельным резервуарам. Жидкости разных типов не
смешиваются; слив сохраняется в NBT. Бур сохраняет прежнее автоматическое
втягивание жидкости из соседнего обработчика; для труб направления потока
настраиваются средствами соответствующего мода. Ведро также работает в обе
стороны. Бур не производит жидкостных побочных продуктов: выход позволяет
забирать жидкость из его баков.

## Начальный баланс и расширение

В мод включён сухой рецепт `ores_and_drills:drill_mining/ordinary_ores` для
`#c:ores`; существующим рудам новые расходы не назначены. Готовый пример
датапака лежит в `examples/datapacks/drill-mining`: скопируйте всю эту папку в
`<world>/datapacks/` и выполните `/reload`, чтобы золото требовало 100 mB воды и
бур уровня 3. В примере специальная добыча ограничена Верхним миром; ручной дроп
золота блокируется во всех измерениях, поскольку рецепт существует.

Новые жидкости и входные блоки добавляются только JSON. Дополнительные типы
условий добавляются через `DrillMiningCondition.register(id, mapCodec)` при
инициализации расширения на сервере и клиенте, до загрузки рецептов. Новому буру
можно задать независимый `recipeLevel` через конструктор `MiningDrillTier`.
Другие виды рецептов регистрируются отдельными `RecipeType`/`RecipeSerializer`;
тип добычи не подменяет систему рецептов Minecraft.

Стандартный сухой рецепт создаёт `DrillMiningRecipeProvider`; команда
`gradlew.bat runData` работает в отдельной папке `build/recipe-datagen` и
обновляет `src/generated/resources`. JSON ресурсов входит в проект; служебный
кэш генератора игнорируется. Индекс рецептов ограничен менеджером рецептов и
числом зарегистрированных блоков; сбрасывается при смене рецептов и тегов,
вместе с кэшем оценки количества дропа.

## Проверка

GameTest проверяют JSON и сетевой обмен, отклонение некорректных рецептов,
приоритет специального рецепта, удаление рецептов при обновлении менеджера,
поиск настоящей руды в залежи, недостаточную и неверную жидкость, полный выход,
возобновление добычи, один расход на многоресурсный цикл, точное истощение,
сухую добычу, минимальный уровень, условия, паузу расхода энергии, ручную добычу,
оба порта при четырёх направлениях установки, симуляцию, сохранение и передачу
между обработчиками без потери жидкости. Тестовые рецепты не попадают в JAR.

Итоговая проверка: **127 JUnit и 27 GameTest прошли**, включая настоящее разрушение
обычной руды и `ore_deposit` киркой через `ServerPlayerGameMode.destroyBlock`;
`build` и `runData` успешны. Логи: `build/drill-fluid-depletion.log` и
`build/drill-recipes-datagen.log`. Готовый пример упакован в
`build/distributions/drill-mining-example.zip` (корень содержит `pack.mcmeta`).

Основные изменения: `ModRecipes`, `DrillMiningRecipe`, `DrillMiningInput`,
`DrillMiningCondition`, `DrillMiningRecipes`, `DrillMiningFluid`, `FluidLockedOreDrops`,
`DrillMiningRecipeProvider`, `DrillMiningJeiPlugin`; расширены существующие
`AbstractDrillBlockEntity`, `AbstractEnergyDrillBlockEntity`, `OreScanner`,
`MiningDrillTier`, `DrillStructure`, `OreDepositBlock` и `OreDepositData`.

Официальное описание использованных RecipeType/MapCodec/StreamCodec:
[документация NeoForge 1.21.1](https://docs.neoforged.net/docs/1.21.1/resources/server/recipes/).
