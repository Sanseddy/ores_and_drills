# Повторное ревью MEDIUM / LARGE

Изменения внесены непосредственно в существующий генератор. TINY/SMALL, их формулы запасов и размещение сохранены. Историческая геометрия находится только в тестовом текстовом снимке для сравнения; второй производственной системы генерации нет.

## Найденные расхождения и исправления

| Проблема предыдущей реализации | Исправление |
|---|---|
| Жёсткий центральный диск и отсечение по окружности подавляли асимметрию | Диск удалён; используется поле конуса, градиентные октавы, подблочное смещение и выбор уровня поля |
| Независимые seed октав и слабый нормированный value noise давали слишком похожие маски | Октавы XZ используют один seed, градиентный шум и больший контраст под компактную сетку |
| Фиксированный перепад Y усиливал почти плоский шум до крутых ступеней | Амплитуды зависят от фактического диаметра; слабые фазы заменяются ограниченным поиском без усиления; шаг центра ограничен .85 / 1.0 |
| Повторная декорация после добычи могла восстановить руду | Завершённые части сохраняются по ID залежи и чанку; отметка остаётся после добычи и NBT-перезагрузки |
| Совпадение типа руды и количества ошибочно могло считаться доказательством общей залежи | Принадлежность определяется отметкой завершения; неизвестный рудный блок отклоняет новый план |
| Части конкурирующих залежей зависели от порядка вызовов | До записи сравниваются постоянные приоритеты потенциально пересекающихся планов; проигравший план целиком не размещается |
| Между записью блока и attachment существовало окно для другого компактного генератора | Короткий замок на этап записи, предварительная подготовка всей части, откат при отказе записи |
| Индекс всегда считал одну секцию | Учитываются реальные уникальные секции каждой части; повторное подтверждение не увеличивает счётчики |
| Около границ высоты тело могло обрезаться | Базовая Y детерминированно подгоняется под полную высоту тела; слишком низкий мир отклоняется |
| Кэш мог одновременно строить один план несколько раз | Общий ограниченный загрузочный LRU: один незавершённый расчёт на ключ, разные ключи строятся вне замка |
| Много копий массивов и повторных смещений шума | Массив поля изменяется на месте; фазы шумов рассчитаны один раз; Y вычисляется только внутри маски; готовый список не сортируется повторно |
| После фильтрации пород отдельный блок мог получить непропорциональный запас | Дополнительная вместимость `min(5000,max(ceil(Q/n),ceil(Q/5)))`, с точным перераспределением остатка |

## Сопоставление с Factorio

Повторно изучены [noise-functions.lua](https://github.com/wube/factorio-data/blob/master/core/prototypes/noise-functions.lua), [resource-autoplace.lua](https://github.com/wube/factorio-data/blob/master/core/lualib/resource-autoplace.lua) и [документация noise expressions](https://lua-api.factorio.com/latest/auxiliary/noise-expressions.html#spot_noise).

`spot_noise` выбирает региональные конусы, возвращая максимум их высот. Пик конуса определяется запасом и радиусом; Lua добавляет многомасштабные деформации и использует полученное поле для вероятности и богатства. Штатная относительная амплитуда обычных пятен — 1/8 типичного пика; радиус ограничивается 32. Это объясняет округлую основу, асимметричный контур и связанные области богатства.

В Minecraft сохранены существующие сетки и выбор материалов. Адаптируется отдельный конус: распределение региональных spot_noise, starting area, distance scaling и межресурсные skip_span не портируются. Градиентный шум заменяет движковый basis_noise; его точная реализация в данных Lua отсутствует. Амплитуда .38 и масштабы ниже — настройки адаптации, а не оригинальный код Factorio.

Для сравнения вычислены 100 ориентиров по документированной модели конуса и штатной амплитуде 1/8, с заменой basis_noise градиентным шумом. Это вычисленные поля, а не нарисованные иллюстрации. При дискретизации ориентиров получено 70 разных масок шириной 5 и 100 шириной 7. Настоящий движок Factorio не запускался: исполняемый файл не найден в PATH и проверенных стандартных Steam-каталогах. **Сходство с точным выводом движка остаётся предметом ручной проверки.**

## Конкретные формулы новой адаптации

`D0=2R`, `R=clamp(k*cbrt(Qbase)*Size^.20,Rmin,Rmax)`; Rmax=2.5 / 3.5. Жёсткий предел общей ширины X/Z — 5 / 7 блоков. Под диаметром блокового пятна здесь понимается `max(widthX,widthZ)`; это не радиус.

```text
s8  = max(1.25,D0/6)
s24 = D0/2
s64 = 4*D0/3
B(p) = G(p/s8) + G(p/s24) + 1.5*G(p/s64) - 1/3
Fraw(x,z) = R/4 * sum_delta[1 - length((x,z)+delta-jitter)/R + .38*B]
delta in {(-.25,-.25),(-.25,.25),(.25,-.25),(.25,.25)}
Fxz = Fraw + level
```

Jitter лежит в пределах ±.35 блока. Уровень сначала обеспечивает положительный центр, затем при необходимости увеличивается шагами .08 до минимальных размеров 3 / 5 по обеим осям; цикл ограничен 128 шагами. Сохраняется четырёхсвязная компонента центра. Всё это происходит до Y; смена вертикального seed не меняет XZ.

```text
D = max(actualWidthX,actualWidthZ)
Ywave = .35*(D-1)*N(x/(.9D),z/(.9D)) + .08*(D-1)*N(x/(.45D),z/(.45D))
```

Проверяются максимум четыре фазы, чтобы не попасть в случайно почти постоянный участок поля. Поиск прекращается при диапазоне `.28*(D-1)`; если он не достигнут, берётся лучшая естественная фаза. Деления на наблюдаемый диапазон нет. Общая поправка уклона может только уменьшить амплитуду: `min(1,stepLimit/maxAdjacentStep)`.

Толщина ограничена 2–4 / 3–5. Независимые верхний и нижний шумы имеют амплитуды .18 / .05 и масштабы `10D/16` / `4D/16`; фактическая толщина повторно ограничивается. Размещение допускается при `Fxz>0 && bottom<=y<=top`. Дополнительный предел числа слоёв исключает лишний слой при целочисленном совпадении обеих границ.

Богатство: `clamp(.10+.55H+.35V+.25Nr,.03,1)`. Минимальные 2 / 3 слоя сохраняют реальные шестисвязные соединения; внешние слои растут по весу. Целочисленный запас распределяется пропорционально весам с ограничением вместимости и коррекцией остатка. Для допустимых маленьких тел минимум в 6 блоков позволяет ограничить один блок 20% суммарного запаса с округлением вверх.

Новая форма имеет выступы и впадины; длинной центральной оси нет. На сетке 3–7 блоков отдельные контуры всё равно могут совпасть или выглядеть симметрично. Решение без увеличения размера — подблочные пробы, переменная фаза, богатство и вертикальные поверхности; получить все детали пятна шириной в десятки тайлов на такой сетке невозможно.

## Производительность и воспроизводимость

```powershell
$env:JAVA_HOME='C:/Program Files/Java/jdk-21.0.11'
.\scripts\review-compact-deposits.ps1 -RecordProfile
.\gradlew.bat build runGameTestServer -PcompactGameTests --console=plain
```

Скрипт компилирует неизменённый тестовый снимок предыдущей геометрии и актуальную версию, использует одинаковые seed, heap 512 MiB, SerialGC, 3000 прогревочных построений и медиану пяти пакетов по 2000 построений. В последнем прогоне без JFR: **37.56 → 24.02 мкс на геометрию**, **14492 → 8416 байт на построение**. Результаты меняются с прогревом и нагрузкой машины; это микроизмерение, а не обещание ускорения всего мира. Размеры фактических тел изменились вместе с алгоритмом.

Кэш геометрии: около .18 мкс на попадание, 20000 попаданий после 100 загрузок. Завершённая часть чанка возвращается до проверки пород. JFR записывается отдельно после прогрева; его измерения не смешиваются с приведённым сравнением. [Сводка JFR](../build/reports/deposit-review/jfr-summary.txt) указывает основные затраты в конструкторе и поле богатства; главные оставшиеся выделения — массивы, Cell и Column. Системные переменные окружения и свойства в запись не включаются.

Отдельный серверный профиль использует настоящий NoiseBasedChunkGenerator Нижнего мира, полный путь построения плана, выбор биома, base columns, фильтрацию пород и распределение запаса. Из 24 кандидатов принято 22; кэш дал 2400 попаданий при 24 загрузках. Первый вызов: медиана 4.77 мс, 0.83 МБ выделений; попадание: медиана 1.80 мкс. Основной дорогой этап — запрос пород, а не геометрия. Подробности: [terrain-plan-profile.csv](../build/reports/deposit-review/terrain-plan-profile.csv). Эти значения относятся к указанному прогону и не являются сравнением полного Minecraft-сервера до/после.

Геометрический кэш ограничен 256 результатами, плановый — 512 на мир; незавершённые загрузки живут только до окончания запросов. Многопоточные тесты проверяют единственный расчёт одинакового ключа, независимую загрузку разных ключей, восстановление после ошибки и вытеснение LRU.

## Подтверждённые проверки и ограничения

Сборка успешна: **124 JUnit, 5 GameTest, ошибок нет**. Проверены 512 геометрий, независимость XZ/Y, реальные шестисвязные блоки, верх/низ, запас и вместимость, крайние Size/Richness, аномальные входы, отрицательные координаты и высоты до -2032 / +1024 в чистой математике. Серверные проверки покрывают порядок частей, конкурирующие планы, жидкость, повторные вызовы после добычи, сохранение NBT, счётчики блоков/секций, forced-ledger и шумовое построение планов.

Сохраняются ограничения:

- Forced сохраняет прежний ledger и зависимый от порядка выбор мест; эта оговорка согласована пользователем. Меняются только компактная геометрия и её запасы.
- Арбитраж AABB консервативен: иногда отклоняет планы, чьи реальные блоки могли бы не соприкасаться. Частота фактических месторождений может уменьшиться.
- Тесты подтверждают отсутствие швов при фиксированных настройках и пригодном породном окружении, а также конкуренцию компактных планов. Сторонние структуры/генераторы или изменения ещё не обработанного участка между вызовами могут изменить окружение; совместимость всей сборки требует проверки в игре.
- Клиентский обход мира, реальные инструменты добычи, произвольные custom dimensions и длительный замер TPS/генерации тысяч чанков вручную не выполнялись. Уже сохранённые залежи не мигрируются; сравнение относится к новым залежам.
- Нативный Factorio preview нужен для окончательного визуального сравнения с движком, вместо использованного документированного математического ориентира.

Ресурсы производства не менялись. Для дополнительной проверки генерируемых datapack-ресурсов используйте `.\gradlew.bat runData`.
