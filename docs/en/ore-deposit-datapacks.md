# Datapacks: deposits and presets

[Русская версия](../ru/ore-deposit-datapacks.md)

A datapack can define where and which deposits appear (deposit rules) and change the default ore
settings (presets). How generation works overall is described in [ore-deposits.md](ore-deposits.md).

## Deposit rules

A rule is an ordinary NeoForge biome modifier. The file goes into
`data/<namespace>/neoforge/biome_modifier/<name>.json`.

Biome modifiers are read when a world loads, so rejoin the world after a change: `/reload` does not
update them. A rule applies only to new chunks.

A ready-made datapack with tin deposits in the Overworld:
[examples/datapacks/ore-deposits](../../examples/datapacks/ore-deposits). Copy the folder into
`<world>/datapacks/`.

### Example

```json
{
  "type": "ores_and_drills:ore_deposit_rule",
  "ores": ["minecraft:diamond_ore", "#c:ores/tin"],
  "biomes": ["minecraft:dripstone_caves", "#minecraft:is_mountain"],
  "dimensions": ["minecraft:overworld"],
  "min_y": -48,
  "max_y": 32,
  "replaceables": ["#minecraft:base_stone_overworld", "create:limestone"],
  "priority": 10,
  "sizes": {
    "tiny": {
      "forced": true,
      "count": 2,
      "placement": "prefer_cave_wall",
      "size_multiplier": 0.8,
      "richness_multiplier": 1.0
    },
    "small": {
      "frequency": 1.25,
      "placement": "underground"
    },
    "large": {
      "frequency": 0.05,
      "placement": "underground",
      "size_multiplier": 1.2
    }
  }
}
```

### Rule fields

| Field | Meaning | Default |
|---|---|---|
| `ores` | ores: block IDs or tags (`#c:ores/tin`) | required |
| `sizes` | per-size settings: `tiny`, `small`, `medium`, `large` | required |
| `biomes` | biomes: IDs or tags | `["#minecraft:is_overworld"]` |
| `dimensions` | dimensions | `["minecraft:overworld"]` |
| `min_y`, `max_y` | height range | −64 and 320 |
| `replaceables` | rock the deposit may replace | `["#c:stones"]` |
| `priority` | priority among rules | 0 |

A value starting with `#` is a tag. Unknown block IDs, empty tags and unknown biomes simply match
nothing and raise no error.

### Size settings

A size missing from `sizes` is not generated by the rule.

| Field | Meaning | Default |
|---|---|---|
| `frequency` | expected deposits per grid cell of this size, 0 to 64 | 0 |
| `forced` | `true`: an exact number of deposits per biome instance instead of a frequency roll | `false` |
| `count` | deposits per biome instance with `forced`, 1 to 64 | 1 |
| `placement` | where the deposit lies, see below | `default` |
| `size_multiplier` | size multiplier | 1.0 |
| `richness_multiplier` | reserve multiplier | 1.0 |

`frequency: 1.25` means one deposit for sure and a second one with a 25% chance. The chance is
deterministic: the same world always gets the same result.

`placement` values:

- `prefer_cave_wall`: look for a cave wall first; without one, the deposit lies inside the rock;
- `cave_wall`: only on a cave wall, with no fallback;
- `underground`: inside the rock, walls are not searched;
- `default` (when the field is omitted): on a wall for `tiny` and `small`, inside the rock for the
  others.

### Forced

A biome instance is one cave or one connected patch of a biome. For mods that lay biomes out in regions
(Alex's Caves), an instance is a region. Patches too large to walk are counted per grid cell.

- A chunk takes a slot only once its deposit is actually built. If a chunk has no suitable rock, the
  slot goes to another chunk of the same instance.
- Deposits of one instance keep their distance from each other.
- Biome, dimension, height, `replaceables` and `placement` are checked as usual: `forced` never places a
  deposit where the rule forbids it.
- A forced deposit appears as its chunk generates; only then does `/locate` find it.

In 3D biomes, such as underground caves, the mod walks columns across the whole cell and picks a center
that really lies in the right biome. Generation and `/locate` do this identically and without loading
distant chunks.

### How rules combine

- If several rules match the same ore, biome and size, the one with the highest `priority` wins. On a
  tie a hash of the rule decides, so datapack load order changes nothing.
- Once an ore has at least one rule, its automatic generation stops. The ore appears only in the biomes
  and dimensions of its rules.
- The layout depends on the world seed, dimension, biome, ore, size, cell coordinates and the rule's
  content. Generation and `/locate oredeposit` compute it identically.
- A changed rule gives a new layout in new chunks.

## Ore settings presets

A preset sets Frequency, Size, Richness and on/off for ores, the same as the "Ore Settings" screen but
from a datapack. The file goes into `data/<namespace>/ore_settings_presets/<path>.json`. The
`ore_deposits.active_preset` config option selects the active preset; the default is
`ores_and_drills:default`.

```json
{
  "defaults": {"enabled": true, "frequency": 1.0, "size": 1.0, "richness": 1.0},
  "ores": [
    {"target": "#c:ores/tin", "frequency": 1.5},
    {"targets": ["minecraft:diamond_ore", "minecraft:deepslate_diamond_ore"], "richness": 2.0},
    {"target": "minecraft:coal_ore", "enabled": false}
  ]
}
```

- `defaults` applies to every ore. Entries from `ores` are layered on top in order, each changing only
  its own fields.
- An ore is selected with `target` or a `targets` list: block IDs and tags.
- Tag entries apply before entries for specific blocks, so a block beats a tag.
- Multipliers are clamped to 0.1–6.
- If the active preset is not found, every value is 1.0.

## KubeJS

KubeJS is not required. If a pack already has it, a rule can come from a script: KubeJS puts the JSON
into its virtual datapack, and the mod reads it like any other file.

```js
ServerEvents.generateData('after_mods', event => {
  event.json('kubejs:neoforge/biome_modifier/custom_tin_deposits', {
    type: 'ores_and_drills:ore_deposit_rule',
    ores: ['#c:ores/tin'],
    // remaining fields as in a JSON rule
  })
})
```
