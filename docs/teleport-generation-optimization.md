# Задержка загрузки чанков при телепортации

## Причина

Во время зависания работающего клиента сняты два дампа потоков:
`build/teleport-threads.txt` и `build/teleport-threads-second.txt`.
В обоих поток `worldgen` выполнял `NoiseBasedChunkGenerator.getBaseColumn` из
`OreDepositFeature.buildCompactPlanAt`, вызванного через `placeForcedCompact`.
Сервер ожидал завершения генерации чанка.

Прежний локальный кэш сохранял результат отдельно для каждой XZ-колонки.
Однако для первого блока каждой колонки Minecraft создавал новый `NoiseChunk`,
обходил граф плотности и рассчитывал столбец по всей высоте мира. Для LARGE
это тысячи повторных созданий графа и гигабайты временных выделений.

## Исправление

`CompactDepositTerrain` использует штатный `NoiseChunk` с общим расчётом для
всех нужных позиций одного чанка. Позиции группируются по интерполяционным
ячейкам; расчёт плотности ограничен диапазоном Y залежи. Граничные точки
интерполяции вычисляются в мировых координатах. Поиск предварительной поверхности
для аквиферов сохраняет исходный полный диапазон высоты; вспомогательный расчёт
поверхности создаётся лениво и переиспользуется внутри чанка.

`NoiseBasedChunkGeneratorAccessor` предоставляет штатный `globalFluidPicker`.
Защищённый маркер отсутствия структур получен через публичный unit codec движка.
Для сторонних подклассов генератора и нестандартных ячеек, не делящих 16,
сохраняется вызов их собственного `getBaseColumn`.

`OreDepositFeature` применяет пакетный расчёт при построении MEDIUM/LARGE,
а также при редком восстановлении базовой породы под уже созданным гравием.
Восстановление ограничено позицией залежи и текущим доступным чанком;
в соседние неготовые чанки нет обращений. В обработчик размещения гравия
дорогие расчёты не добавлены.

Формулы геометрии, seed, запасы, правила замены, forced-учёт, TINY/SMALL и
форматы сохранения не изменены. Кэш результатов расчёта породы живёт только
в пределах одной операции.

## Проверка

Команда: `./gradlew.bat build runGameTestServer -PcompactGameTests --console=plain`.
Прошли 124 JUnit и 15 GameTest. Дополнительный тест выполнил 42 876 точных сравнений со
штатным `getBaseColumn` в Overworld/Nether/End с двумя seed, отрицательными
координатами, границами чанков и шумовых ячеек, воздухом, жидкостями,
обратным порядком обхода, узкими окнами Y, обрезанной высотой мира и
нестандартными ячейками шириной 12 блоков. Отдельно сравнивается полная LARGE.

В изолированном тесте для LARGE из 18 346 позиций, после прогрева,
медиана трёх измерений проверки базовой породы:

| Показатель | Прежний расчёт | Пакетный расчёт |
|---|---:|---:|
| Время | 7 235 мс | 57,7 мс |
| Выделения текущего потока | 3 585 МБ | 33,9 МБ |

В этом замере этап ускорился примерно в 125 раз, выделения снизились примерно
на 99%. Это сравнение одного этапа генерации, а не времени телепортации целиком.
Сырые измерения: `build/reports/factorio-deposits/terrain-batch-profile.csv`.
Успешный итоговый запуск: `build/teleport-optimization-final.log`.
Профиль полных планов: `build/reports/factorio-deposits/terrain-plan-profile.csv`.
Время пользовательской сборки после исправления ещё нужно проверить после
перезапуска клиента; оно также включает обычную генерацию, остальные моды,
дисковый ввод-вывод и отправку чанков.
