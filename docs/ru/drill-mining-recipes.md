# Рецепты добычи буром

[English version](../en/drill-mining-recipes.md)

Рецепт добычи говорит буру, как разрабатывать конкретную руду: нужна ли жидкость, какой бур подходит, при
каких условиях и что получается на выходе. В моде есть один рецепт по умолчанию: все руды из `#c:ores`
добываются без жидкости и дают свой обычный дроп. Остальное добавляют датапаки.

Рецепты лежат в `data/<namespace>/recipe/<путь>.json` (папка `recipe`, в единственном числе) и
перезагружаются командой `/reload`, пересоздавать мир не нужно. Клиент получает их от сервера; JEI и
EMI показывают их в категории «Добыча буром».

## Пример

```json
{
  "type": "ores_and_drills:drill_mining",
  "input": "#c:ores/uranium",
  "fluid": {"tag": "c:sulfuric_acid", "amount": 100},
  "minimum_drill_tier": 3,
  "priority": 10,
  "conditions": [
    {"type": "ores_and_drills:dimension", "dimension": "minecraft:overworld"},
    {"type": "ores_and_drills:height", "min": -64, "max": 16}
  ]
}
```

## Поля

| Поле | Что задаёт | По умолчанию |
|---|---|---|
| `input` | какие блоки добывает рецепт | обязательное |
| `fluid` | жидкость, которая тратится за цикл | без жидкости |
| `minimum_drill_tier` | самый слабый подходящий бур, от 1 | 1 |
| `conditions` | условия, которые проверяются при добыче | без условий |
| `priority` | приоритет среди рецептов одного блока | 0 |
| `result` | что получается вместо обычного дропа | обычный дроп руды |
| `neoforge:conditions` | загружать ли рецепт вообще | всегда |

### `input`

Тег блоков (`"#c:ores/gold"`) или список ID (`["minecraft:gold_ore", "minecraft:deepslate_gold_ore"]`).
Даже один блок записывается списком. Блоки не обязаны быть в теге руд.

### `fluid`

Жидкость и её расход в mB (1000 mB — одно ведро). Расход должен быть положительным и не больше бака
бура, иначе бур будет ждать жидкость вечно. Варианты записи:

- конкретная жидкость: `{"id": "minecraft:water", "amount": 100}`;
- тег: `{"tag": "c:sulfuric_acid", "amount": 100}`, без `#`;
- стандартный ингредиент NeoForge: `{"fluid": "minecraft:water", "amount": 100}`.

`id` и `tag` вместе указывать нельзя. В `id` пишется ID жидкости, например
`modern_industrialization:sulfuric_acid`, а в `tag` — имя тега, например `c:sulfuric_acid`.

### `minimum_drill_tier`

| Уровень | Бур | Баки |
|---:|---|---|
| 1 | Твердотопливный | нет |
| 2 | Электрический | нет |
| 3 | Продвинутый | 2 × 10 000 mB |
| 4 | Совершенный | 2 × 20 000 mB |

Баки есть только у продвинутого и совершенного буров, поэтому рецепт с `fluid` требует уровень не ниже 3:
значения 1 и 2 считаются как 3.

Кроме уровня рецепта бур проверяет, добыла бы руду его кирка: твердотопливный — как каменная,
электрический — как железная, продвинутый — как алмазная, совершенный — как незеритовая. Поэтому
алмазную руду твердотопливный бур не возьмёт даже по рецепту уровня 1.

JEI и EMI показывают итоговое требование слотами буров в левом нижнем углу страницы: там только те буры,
которые действительно добудут руду. Надпись «Минимальный уровень бура» появляется, лишь если рецепту не
подходит ни один бур из мода.

### `conditions`

Все условия должны выполняться одновременно.

| Условие | Пример |
|---|---|
| измерение | `{"type": "ores_and_drills:dimension", "dimension": "minecraft:overworld"}` |
| высота руды, включительно | `{"type": "ores_and_drills:height", "min": -64, "max": 16}` |
| тег биома в точке руды | `{"type": "ores_and_drills:biome", "tag": "c:is_overworld"}` |
| сигнал редстоуна на главном блоке бура | `{"type": "ores_and_drills:redstone", "powered": true}` |

У `height` можно указать только `min` или только `max`. У `redstone` по умолчанию `powered: true`.

### `result`

Предмет, например `{"id": "minecraft:raw_gold", "count": 2}`. Без этого поля бур получает обычный дроп
руды. Один результат соответствует одной единице запаса; бонус продуктивности бура добавляется сверху.

### `neoforge:conditions`

Стандартные условия загрузки NeoForge, например загрузить рецепт, только если установлен определённый
мод. Они проверяются один раз при загрузке рецептов, а `conditions` — при каждой добыче.

## Какой рецепт выбирается

Для каждого блока работает только один рецепт. Порядок выбора:

1. больший `priority`;
2. рецепт с жидкостью раньше рецепта без неё;
3. список блоков раньше тега;
4. ID рецепта по алфавиту.

Если условия выбранного рецепта не выполняются, бур этот блок пропускает и ничего не тратит.
Запасного перехода на рецепт попроще нет. Два рецепта с разными жидкостями для одного блока не
взаимозаменяемы: какой из них работает, решает `priority`.

## Как бур тратит жидкость

- Бур смотрит оба бака и берёт тот, где подходящей жидкости хватает на целый цикл. Разные жидкости из
  одного тега не складываются: 50 mB одной и 50 mB другой не заменят 100 mB.
- Жидкость списывается один раз за цикл на каждый сработавший рецепт. Если цикл не удался (выход забит,
  жидкость не та, добыча сорвалась), жидкость не тратится.
- Пока руда ждёт жидкость, бур добывает другие доступные руды в своей зоне. Если добывать нечего,
  прогресс и расход энергии останавливаются; уже зажжённое топливо твердотопливного бура догорает, как в
  печи.
- Пустой тег не делает добычу бесплатной: бур будет ждать жидкость.

Жидкость подаётся трубами через два боковых порта продвинутого и совершенного буров. Порты работают в
обе стороны и подключены к общим бакам; бур также сам втягивает жидкость из соседнего хранилища.
Ведро тоже можно заливать и сливать. Баки сохраняются вместе с буром.

## Руда, которой нужна жидкость

Если у руды есть хоть один рецепт с жидкостью, получить её можно только буром из мода. Это работает
всегда, даже если условия рецепта сейчас не выполняются.

- Кирка, молоты, машины других модов и взрывы ломают такую руду без дропа и опыта. У залежи каждое
  такое разрушение просто сжигает одну единицу запаса.
- Jade показывает на такой руде «✕ Нельзя добыть вручную» и «Нужен бур с жидкостью».

Блокировка смотрит на загруженные рецепты, а не на файлы. Если в логе есть
`Parsing error loading recipe ... Unknown registry key ... minecraft:fluid`, рецепт не загрузился и не
действует. Частая причина — тег в поле `id`: `{"id": "c:sulfuric_acid"}` вместо
`{"tag": "c:sulfuric_acid"}`.

## Теги жидкостей

Свой тег жидкостей добавляется файлом `data/<namespace>/tags/fluid/<имя>.json` с массивом `values`.
Состав тегов обновляется по `/reload` вместе с рецептами. JEI показывает все жидкости тега, кроме
дублей с одинаковым названием.

## Примеры

Датапак [examples/datapacks/drill-mining](../../examples/datapacks/drill-mining): скопируйте папку в
`<мир>/datapacks/` и выполните `/reload`.

- `wet_gold.json` — минимальный: золото требует 100 mB воды и продвинутый бур, только в Верхнем мире.
- `all_options.json` — все поля сразу. Красную руду добывает только совершенный бур, с 250 mB жидкости
  из тега `minecraft:water`, в Верхнем мире, на высоте от −64 до 16, в биомах `c:is_overworld` и только
  при сигнале редстоуна. За единицу запаса выходит 8 пыли редстоуна. `priority: 20` ставит рецепт выше
  остальных для этих блоков, `neoforge:conditions` загружает его, только если установлен Ores & Drills.

С этим датапаком золото и красная руда перестают выпадать при ручной добыче во всех измерениях: у них
появились рецепты с жидкостью.

## Для разработчиков

- Новые жидкости и блоки добавляются только JSON.
- Свой тип условия регистрируется через `DrillMiningCondition.register(id, mapCodec)` при инициализации
  мода на сервере и клиенте, до загрузки рецептов.
- Новому буру можно задать свой уровень рецептов через канонический конструктор `MiningDrillTier`.
- Рецепт по умолчанию генерирует `DrillMiningRecipeProvider` (`gradlew runData`).
- Основные классы: `DrillMiningRecipe`, `DrillMiningRecipes`, `DrillMiningFluid`, `DrillMiningCondition`,
  `FluidLockedOreDrops`, `DrillMiningJeiPlugin`, `DrillMiningEmiPlugin`. Устройство рецептов NeoForge —
  в [документации NeoForge 1.21.1](https://docs.neoforged.net/docs/1.21.1/resources/server/recipes/).
