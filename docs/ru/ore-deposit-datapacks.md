# Датапаки: месторождения и пресеты

[English version](../en/ore-deposit-datapacks.md)

Датапак может задать, где и какие залежи появляются (правила месторождений), и поменять настройки руд по
умолчанию (пресеты). Как устроена генерация в целом, описано в [ore-deposits.md](ore-deposits.md).

## Правила месторождений

Правило — обычный biome modifier NeoForge. Файл кладётся в
`data/<namespace>/neoforge/biome_modifier/<имя>.json`.

Biome modifier читаются при загрузке мира, поэтому после изменений нужно перезайти в мир: `/reload` их
не обновляет. Правило действует только в новых чанках.

Готовый датапак с залежами олова в Верхнем мире: [examples/datapacks/ore-deposits](../../examples/datapacks/ore-deposits).
Скопируйте папку в `<мир>/datapacks/`.

### Пример

```json
{
  "type": "ores_and_drills:ore_deposit_rule",
  "ores": ["minecraft:diamond_ore", "#c:ores/tin"],
  "biomes": ["minecraft:dripstone_caves", "#minecraft:is_mountain"],
  "dimensions": ["minecraft:overworld"],
  "min_y": -48,
  "max_y": 32,
  "replaceables": ["#minecraft:base_stone_overworld", "create:limestone"],
  "priority": 10,
  "sizes": {
    "tiny": {
      "forced": true,
      "count": 2,
      "placement": "prefer_cave_wall",
      "size_multiplier": 0.8,
      "richness_multiplier": 1.0
    },
    "small": {
      "frequency": 1.25,
      "placement": "underground"
    },
    "large": {
      "frequency": 0.05,
      "placement": "underground",
      "size_multiplier": 1.2
    }
  }
}
```

### Поля правила

| Поле | Что задаёт | По умолчанию |
|---|---|---|
| `ores` | руды: ID блоков или теги (`#c:ores/tin`) | обязательное |
| `sizes` | настройки по размерам: `tiny`, `small`, `medium`, `large` | обязательное |
| `biomes` | биомы: ID или теги | `["#minecraft:is_overworld"]` |
| `dimensions` | измерения | `["minecraft:overworld"]` |
| `min_y`, `max_y` | диапазон высот | −64 и 320 |
| `replaceables` | породы, которые залежь может заменить | `["#c:stones"]` |
| `priority` | приоритет среди правил | 0 |

Значение с `#` в начале — тег. Несуществующие ID блоков, пустые теги и неизвестные биомы ничего не
выбирают и ошибки не вызывают.

### Настройки размера

Размер, которого нет в `sizes`, правило не генерирует.

| Поле | Что задаёт | По умолчанию |
|---|---|---|
| `frequency` | ожидаемое число залежей в ячейке сетки этого размера, от 0 до 64 | 0 |
| `forced` | `true` — точное число залежей на экземпляр биома вместо броска частоты | `false` |
| `count` | число залежей на экземпляр биома при `forced`, от 1 до 64 | 1 |
| `placement` | где лежит залежь, см. ниже | `default` |
| `size_multiplier` | множитель размера | 1,0 |
| `richness_multiplier` | множитель запаса | 1,0 |

`frequency: 1.25` означает одну залежь наверняка и вторую с вероятностью 25 %. Вероятность
детерминирована: в одном и том же мире результат всегда одинаковый.

Значения `placement`:

- `prefer_cave_wall` — сначала ищется стена пещеры, если её нет, залежь ложится в толщу породы;
- `cave_wall` — только у стены пещеры, без запасного варианта;
- `underground` — в толще породы, стены не ищутся;
- `default` (если поле не указано) — у стены для `tiny` и `small`, в толще породы для остальных.

### Forced

Экземпляр биома — это одна пещера или одно связное пятно биома. У модов, которые размечают биомы
регионами (Alex's Caves), экземпляр — регион. Пятна, слишком большие, чтобы их обойти, считаются по
ячейкам сетки.

- Чанк получает слот, только когда залежь в нём действительно построена. Если в чанке нет подходящей
  породы, слот достаётся другому чанку того же экземпляра.
- Залежи одного экземпляра держатся на расстоянии друг от друга.
- Биом, измерение, высота, `replaceables` и `placement` проверяются как обычно: `forced` не ставит
  залежь туда, где правило её запрещает.
- Forced-залежь появляется вместе с генерацией чанка, и только после этого её находит `/locate`.

В объёмных биомах, например подземных пещерах, мод перебирает колонки по всей ячейке и выбирает центр,
который действительно лежит в нужном биоме. Генерация и `/locate` делают это одинаково и без загрузки
дальних чанков.

### Как правила сочетаются

- Если для одной руды, биома и размера подходят несколько правил, работает правило с наибольшим
  `priority`. При равенстве выбор определяет хеш правила, поэтому порядок загрузки датапаков ничего не
  меняет.
- Если у руды есть хоть одно правило, автоматическая генерация этой руды отключается. Руда появляется
  только в биомах и измерениях из правил.
- Расстановка зависит от seed мира, измерения, биома, руды, размера, координат ячейки и содержимого
  правила. Генерация и `/locate oredeposit` считают её одинаково.
- Изменённое правило даёт новую расстановку в новых чанках.

## Пресеты настроек руд

Пресет задаёт значения «Частота», «Размер», «Богатство» и включение для руд — то же, что экран
«Настройки руды», но датапаком. Файл кладётся в `data/<namespace>/ore_settings_presets/<путь>.json`.
Какой пресет активен, решает параметр `ore_deposits.active_preset` в конфиге; по умолчанию это
`ores_and_drills:default`.

```json
{
  "defaults": {"enabled": true, "frequency": 1.0, "size": 1.0, "richness": 1.0},
  "ores": [
    {"target": "#c:ores/tin", "frequency": 1.5},
    {"targets": ["minecraft:diamond_ore", "minecraft:deepslate_diamond_ore"], "richness": 2.0},
    {"target": "minecraft:coal_ore", "enabled": false}
  ]
}
```

- `defaults` применяется ко всем рудам. Записи из `ores` накладываются поверх по порядку, и каждая
  меняет только свои поля.
- Руда задаётся полем `target` или списком `targets`: ID блоков и теги.
- Записи с тегами применяются раньше записей с конкретными блоками, поэтому блок важнее тега.
- Множители ограничены диапазоном 0,1–6.
- Если активный пресет не найден, все значения равны 1,0.

## KubeJS

KubeJS не нужен. Если он уже стоит в сборке, правило можно создать скриптом: KubeJS кладёт JSON в свой
виртуальный датапак, и мод читает его так же, как обычный файл.

```js
ServerEvents.generateData('after_mods', event => {
  event.json('kubejs:neoforge/biome_modifier/custom_tin_deposits', {
    type: 'ores_and_drills:ore_deposit_rule',
    ores: ['#c:ores/tin'],
    // остальные поля как в JSON-правиле
  })
})
```
